## 1. 当前技术结构及难点

### HTML 与图层

public/index.html 的 section#cover 为 Banner 边界，包含：

1. #heroBg：背景图片层，z-index 0。
2. #heroWall：照片墙，z-index 1，数据来自图库 showInHeroWall 标记，取最多 6 项，CSS 实际隐藏第 6 项及以后。
3. #cover::after：径向光、水平遮罩、垂直遮罩，z-index 2。
4. .hero-copy：辅助眉题、#profileName 主标题、#profileIntro 简介、两个链接按钮，z-index 3。
5. .hero-mark：图库标签、动态图片数量、单位，z-index 3。

Banner 上方导航与下方 stats 不属于 V1 编辑范围，但必须参与重叠和响应式回归检查。

### CSS

public/styles.css 同时定义 Banner 底色/渐变、背景图、伪元素遮罩、文字、按钮、照片墙、统计浮卡、入场动画和移动规则。通用 h1/.lead/.button 也被其他页面使用，不能直接全局改成编辑参数。桌面最低高度 min(720px,100vh)，680px 以下最低高度 580px。移动端文字 padding、浮卡尺寸和照片墙尺寸另有覆盖。

### JS 与内容

public/app.js 的 render() 合并 portfolio.profile 与当前语言 profile；profile.title 同时写入导航品牌名和 Banner 主标题。眉题、按钮和浮卡标签由 data-i18n 处理；图库数字来自 visibleGallery().length。语言切换会调用完整 render()，重建部分 DOM，重新设置背景和入场状态。

背景选择来自 profile.heroImage；否则使用产品营销章节封面，再回退到首个可见图库图片。目前单个 backgroundImage 内联值同时包含图片和水平渐变。仅写一个 CSS 变量无法完整控制它。

现有后台已经有 Banner 图片上传和照片墙素材标记。Visual Lab 必须保持独立草稿，不复用后台保存、上传或发布接口。

### 动画

setupHeroIntro() 等待背景图和照片墙图片预载后，为 .hero-reveal 添加 is-visible。CSS 过渡约 5.2 秒、带分项延迟；7.2 秒后设置 hero-ready。setupHeroMotion() 用 requestAnimationFrame 更新 --hero-x、--hero-y、--hero-scroll。品牌链接可重播入场。

风险在于 transform/opacity 同时承载入场、视差与设计参数；不能用编辑器的 translate/opacity 直接覆盖动画。代码虽声明 --hero-bg-scale，但可见变换仍写死 scale(1.035)，不能误认为现有缩放变量已接通。reduced-motion 的一般规则后面又对 .reveal-item 恢复 5 秒过渡，现有行为不完全一致，V1 需要专门验证而非宣称已正确处理。

## 3. 面板布局与操作流程

推荐独立本地编辑外壳 /__visual-lab/，左侧约 320–360px 的可收起上下文参数面板，右侧同源 iframe 显示真正首页。iframe 加载原 HTML/CSS/JS，真实内宽决定媒体查询，而不是缩小一个桌面截图。

顶部：FEIROO Visual Lab、当前草稿、未保存标记、zh/en、桌面/移动及具体预览宽度。预设宽度含 320/375/390/430/768/1024/1440；768/1024 用于检查过渡，不意味着新增断点。

面板四类：背景与光影、文字、按钮与基础组件、整体布局。默认显示选中对象的常用参数，其余参数进入折叠的高级设置，切换分类不把所有对象的滑块同时展开。底部固定保存草稿与撤销/重做；导入/导出位于顶部方案菜单；恢复默认放在对象设置中并明确作用范围。折叠面板不改变预览宽度；缩放预览只改变展示比例，不改变 iframe 的实际 CSS 视口。

操作流程：打开本地专用命令 → 进入原始预设 → 选择设备与语言 → 点选真实网页中的目标 → 自动展开对应常用参数 → 按需展开高级参数 → 切换设备/语言检查 → 保存具名草稿或导出完整设计包 → 提交设计审核。确认设计后另行执行代码固化。

滑块与数值框双向同步，颜色提供选择器、十六进制值和独立 alpha。按住拖动为一次撤销操作；文字输入按连续输入分组。恢复默认和导入也是可撤销操作。批量操作显示影响范围；中文与英文不会自动互相覆盖。

元素点选是 V1 的主要入口：限定背景、眉题、标题、简介、两按钮、照片墙整体、浮卡整体等已登记对象。编辑模式 hover 高亮并显示名称，单击选中并自动切换对应分类，面板保留选中状态；正常交互模式恢复链接原行为；Esc 取消选中。不是通用 DOM/CSS 编辑器，不选择任意页面元素、不允许拖动改变 DOM 顺序。

背景和光影实际由伪元素或遮挡层组成，不能依赖它们接收点击：点击 Banner 空白区选择背景，再在面板内切换图片/遮罩/光源；点击“Banner 边框”选择整体布局，或使用对象路径“Banner › 主标题”。点击照片墙内的任意图片只选择照片墙整体。分类导航内提供对象列表，与网页点选双向同步；分类选择也可用键盘完成，不要求精确点中细小元素。

主标题常用区只显示当前语言文本、字体、字号、字重、颜色和对齐；行高、字距、透明度、最大宽度及偏移进入高级区。背景常用区显示模式、桌面/移动图片、缩放与位置，滤镜和光影分组展开。按钮常用区显示文案、尺寸、圆角及配色，边框、阴影与 hover 状态另行展开。设备字段始终显示“桌面共用 / 移动继承 / 移动独立”，提供恢复继承，防止用户不知道改动会作用于哪一端。

### 三种操作的明确边界

| 操作 | 用户得到什么 | 修改范围 | 不会连带执行 |

## 5. 参数、图片与适配

### 状态与 CSS 自定义属性

参数模型建议包含 schemaVersion、baseCommit、defaultPresetVersion、assets、content.zh/en、base、desktop、mobile、可选 localeStyles.zh/en。运行值由默认值 → 共用参数 → 对应设备覆盖 → 可选语言样式覆盖合成。空覆盖代表继承，显式透明度 0 不能误当作没有值。

设备覆盖按现有 680px 边界启用；中间尺寸继续沿用原站规则。V1 不开放任意断点。默认保留现有 clamp()/min() 表达式，不把某个视口的 getComputedStyle 像素快照当作所有设备默认值。首个界面显示计算值，并明确某项仍处于“原站自适应/继承”状态。

几何、颜色、字号等参数使用 #cover 范围内的 --feiroo-* 变量。文本和资源 ID 作为数据，由适配器应用。不会修改全站 --accent 或 .button/h1，避免影响后台和其他模块。

本地适配层把底色、图片、遮罩、光影分开管理。图片 filter/opacity 只作用于图片层；设计偏移与动画位移分属不同层或组合变换，最终透明度由设计值与动画进度相乘。保留原始 z-index、链接、语义和动画状态。

### 保存

工作状态在内存，撤销记录也在内存；使用 localStorage 的独立 feiroo.visualLab.v1 命名空间作小型恢复缓存。具名“保存草稿”写入本地 .visual-lab/drafts/，浏览器不支持直接落盘的问题由专用 loopback 服务解决。失败时保留脏状态并允许下载 JSON，不能显示虚假的保存成功。

JSON 只保存参数、相对资源 ID、版本、来源基准；不保存 DOM、HTML、函数、Cookie、绝对磁盘路径或 blob URL。导入先验证 schema、类型、数值上下限、文件大小及资源引用，展示摘要再应用；不识别版本不静默套用。

### 图片

原有 public/assets 图片可以只读引用。新图片通过面板选择并送至专用本地服务，校验 MIME、实际图像类型、大小和解码尺寸，按内容 hash/安全文件名保存于 .visual-lab/assets/。默认支持 JPEG/PNG/WebP/AVIF，SVG、动图和远程 URL 暂不开放。避免读取任意磁盘路径或复用后台上传接口。

桌面与移动分别保存 assetId，移动未设置时继承桌面；各自保存裁切位置与缩放。只加载当前视口需要的图片，切换图片先解码再替换，失败回退原图。模糊层预留边缘扩展以免出现黑边。

### 跨设备完整设计包（V1 必需）

默认导出可在另一台电脑恢复的 `.feiroo.zip` 包。JSON 另保留为轻量参数方式，并明确标注“不包含图片，独立使用不保证完整恢复”。完整包不依赖原电脑的绝对路径、blob URL、浏览器缓存或生产数据库。

```text
方案名称.feiroo.zip
  manifest.json          包版本、设计ID、名称、时间、基准提交、断点
  design.json            全部共用/设备/语言参数及资源ID引用
  assets/                被实际引用的背景图、照片墙图片和必要字体
  context/banner.json    Banner只读内容快照（含默认回退与浮卡显示数量）
  README.txt             恢复步骤、兼容要求、素材/字体来源说明
```

资源收集按“可达引用”执行：桌面图、移动图、继承的默认图、照片墙显示图片、Banner 使用的字体均纳入，不仅打包新上传图片。相同内容按哈希去重，manifest 记录相对路径、MIME、字节数与 SHA-256。若字体依赖本机系统字体，跨设备可能不同，导出前提示并要求改用可随包携带且允许分发的项目字体；无法携带的必要资源要明确列为缺失，不把包标为“完整”。只读内容快照限定 Banner 必要字段，不导出后台全量数据、认证信息、联系人资料或无关图库。

另一台电脑需要安装并运行兼容的本地 Visual Lab 及匹配的项目基准，设计包本身不是独立可执行网站。正常包应携带足够资源，不从远程 URL 补下载。导入时先展示基准、设备、语言、资源清单和兼容结果；当前基准不同则停止自动应用，提示切换到匹配基准或进行独立迁移评估，不自动 checkout、不覆盖现有代码。

导入完整包的流程：选择文件 → 在暂存目录检查 ZIP 与清单 → 验证字段、哈希、大小与资源可解码性 → 展示导入摘要 → 创建新本地草稿与本地资源副本 → 打开预览。原有草稿不覆盖，失败只清理本次暂存文件。导入后使用独立的 Banner 内容快照恢复显示效果；真实站点内容保持不变，并用“导入方案预览数据”标识模拟的图库数量。

限制 ZIP 路径必须为包内相对路径；拒绝路径穿越、绝对路径、符号链接、可执行文件和重复条目；限定条目数、总解压大小与单文件大小，防止异常压缩包。暂定限制：单文件最大 20 MB、整个 ZIP 最大 100 MB、最多 100 个条目（按 1 MB = 1024 × 1024 字节；单文件按解压后的大小计算，压缩包本体和解压总量均不超过 100 MB）。限制写入参数契约；实际 ZIP 导入导出及安全校验实现仍留待后续阶段。打包不新增运行时依赖，首选用现有 Node 运行环境实现受限的标准 ZIP 存储模式，跨平台可读；具体辅助代码也只在方案批准后编写。

恢复验收：电脑A导出完整包 → 电脑B使用匹配基准与空白 Lab 存储导入 → 不依赖A的文件或缓存，恢复桌面/移动、中文/英文、图片与必要字体及动画参数；归一化参数与资源哈希一致，四组预览核对截图。不同系统字体栅格化可能产生细小差别，不承诺逐像素相同。先用同机全新存储模拟一次，再在第二台机器实际验收；未完成真机迁移不宣称跨设备验收已完成。

### 本地服务隔离

专用 lab 服务仅在明确启动命令下运行；绑定回环地址，验证 Host/Origin，对保存和图片接口校验临时会话令牌，路径只能落在指定本地状态目录。iframe 消息验证精确 origin、source 和会话 ID，不用通配 targetOrigin。

预览读取本地数据种子和资源；专用 lab 服务不转发管理员写接口，不加载 Netlify 写入凭据、不调用 Netlify Blobs。普通 npm start 不启用面板。仅依赖 hostname 判断或 ?lab=1 不足以保证生产隔离，因此不作为主要开关。

Netlify 发布目录仍为 public，编辑外壳与所有调试资源在其外；生产首页不含调试 script/link。产物检查必须验证入口与调试资源缺席，而不是只把按钮藏起来。

### 设计固化

用户明确确认指定设计包及另行授权固化 → 从经过校验的包读取确定版本 → 生成人工可审查的 Banner 局部 CSS/内容差异 → 仅将最终采用的图片/字体复制到正式 assets/banner 或对应字体目录 → 为 Banner 单独映射文案，避免修改 profile.title 时连带改变导航品牌 → 关闭 Lab，用普通预览重测 → 提交变更清单给用户。不会将 .visual-lab/、整个设计包或临时资源目录直接复制/提交到生产分支；只处理正式设计实际需要的文件。Git 推送和 Netlify 部署始终是另行授权的步骤。

## 6. 风险与处理

| 风险 | 处理与验收 |
| --- | --- |
| 语言切换覆盖草稿 | 草稿语言状态与原站语言切换同步；render 后重应用当前语言覆盖；不改 portfolio 原对象；反复切换验证 |
| 主标题改动连带导航品牌 | Lab 只改 #profileName；固化时为 Banner 独立文本映射，不全局覆盖 profile.title |
| 动画覆盖参数/拖动明显滞后 | 调参模式只暂停 Banner 自身过渡和视差、展示最终状态；退出恢复；正常动画模式与重播单独验收；不全局取消动画 |
| 替图后等待旧图片或旧计时器回写 | 使用编辑修订号和已解码当前图片；失效回调忽略，重播前清理本次计时器；不让图片错误阻止文字出现 |
| 全屏模糊和实时输入耗性能 | 模糊限制范围和像素；rAF 合并单帧更新，滑块只写目标变量；不重建全站 DOM；不每帧序列化/保存 |
| 默认预设与生产不同 | 比对桌面、移动、两语言和入场完成状态；原始预设不带草稿覆盖；默认组合包含两套现有遮罩 |
| 任意位移/固定高度导致遮挡 | 优先流式布局和最小高度；边界与溢出提示；测试长中英文、200% 文字放大和不同图片比例 |
| 面板缩窄页面造成错误断点 | iframe 使用明确 CSS 宽度，外壳收起与缩放不改其内宽；显示真实预览宽度 |
| 文本/JSON 引入脚本或任意 CSS | textContent 写文本；字段白名单和结构化数值；资源 ID 映射；拒绝路径穿越、脚本和未知字段 |
| 降低动效偏好处理不一致 | 为 Banner 局部提供确定的静态呈现；尊重系统偏好；不顺带修改全站历史动效 |
| 本地草稿与线上数据库不一致 | 清楚显示“本地内容种子”；不通过 Lab 发布后台数据；布局确认后另行评估线上内容差异 |
| 设计包缺少继承资源或字体 | 解析完整资源依赖；完整包导出前检查缺失；导入验哈希；匹配项目基准；空白存储和第二台电脑验收 |
| 点选与按钮导航冲突 | 编辑/正常浏览模式分离；仅注册对象拦截点击；Esc取消选中；分类列表支持键盘选择 |
| 保存/导出误触代码固化 | 三类操作不同位置与名称；导出不清除脏标记；V1不提供一键固化/发布；固化另行授权 |

## 7. 分阶段计划与验收

以下阶段均待用户确认后才开发；批准方案不等于允许上线。

1. **隔离骨架与参数契约**：专用本地入口、真实 iframe、schema、原始预设、最小 bridge。验收：普通预览没有编辑器；Netlify public 产物无编辑文件；原始预设在双语言与桌面/移动保持现有外观；无管理写请求。
2. **背景和光影**：桌面/移动图片、三类背景、分层滤镜、主光源及原有遮罩。验收：亮度/模糊不影响文字，移动图独立，缺图可恢复，无闪白；默认预设可完全恢复。
3. **核心编辑体验**：以网页点选驱动上下文参数面板，分类导航同步；双语言文本、排版、CTA 常态/hover、圆角及整体布局优先，照片墙和浮卡只做基础整体参数。验收：无需展开全部滑块即可完成主标题、按钮与背景编辑；调参只影响 #cover；原链接保留；320/375/390/430/768/1024/1440 无非预期溢出；语言切换保留对应草稿。
4. **完整编辑与迁移流程**：撤销重做、具名草稿、JSON与完整资源设计包导入导出。验收：连续拖动一次撤销；重启本地服务后草稿/图片恢复；空白存储与第二台机器恢复相同参数和资源；基准不匹配/非法包/存储失败有明确反馈；导入创建新草稿不覆盖原草稿；面板支持键盘与可见焦点；保存/导出均不改网站代码。
5. **动效与性能回归**：调参/正常动画切换、重播、减少动态效果、视差和响应式完整验证。验收：调参及时、无抖动闪烁、无失效回调覆盖新参数；与无 Lab 页面比较无持续整页重绘或每次输入网络保存。
6. **设计交付与固化说明**：交付指定完整设计包和文件变更预告，不自动开始固化。只有再次得到明确授权后才进行代码固化演练。验收：授权后关闭 Lab 仍可复现设计；其他页面和后台不受影响；提交正式文件清单和验证结果；无本地草稿/临时资源进入生产文件，不自动推送、部署。

第一版最终边界：背景/光影、文字、双按钮、圆角、整体流式布局为核心；照片墙与浮卡仅整体基础调节；点选与分类导航、双设备双语言、撤销/重做、默认预设、本地草稿、完整设计包与JSON交换均纳入验收。复杂单元素自由排布、多光源、富文本、字体上传、协作、整站编辑和一键代码生成/发布留待后续评估。

本轮只优化本文档，已认可的移动 CSS 修复保持原样。Visual Lab 实现必须等待用户明确确认；确认开发方案也不等于授权代码固化、推送或上线。
